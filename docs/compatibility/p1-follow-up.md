Text responses also expose cumulative response. JSON/document response stays null until final parsing; binary/stream never exposes partial text. Fetch mode retains MonkeySharp's existing suppression of progress and intermediate readyState events. Fixed 5.6.6242 actually emits fetch progress: this is a recorded intentional difference, not parity. UTF-8 decoding uses replacement for malformed bytes; unsupported charset names retain the existing UTF-8 fallback.

The signed Chrome beta CRX is pinned by package hash and publisher signature. Unpacking restores only manifest.key from the publisher proof matching the signed CRX identity; executable files are unchanged. The first acquisition selected the store proof instead of the publisher proof and the first fixture incorrectly expected no fetch progress. That failed run is retained and is not identity-qualified evidence. The corrected publisher run and reproducibly unpacked run are retained separately.

Reproduce with `node scripts/compatibility/Unpack-Reference.cjs <signed.crx> <new-directory>`, then `node scripts/compatibility/Run-Reference.cjs <Edge-exe> <new-directory> <new-output.json> scripts/compatibility/fixtures/p1-progress.user.js scripts/compatibility/reference-beta.json`. The pin rejects a newer package or changed source; Playwright is required. Native reproduction uses the existing SmokeHost Run-E2E.ps1; the binary case now includes delayed chunked text, split UTF-8, gzip and abort/timeout after partial delivery. Existing charset, redirect, response-type and binary checks remain active.

Fixed beta uploads exact stream bytes over the controlled HTTP/2 TLS endpoint; HTTP/1.1 attempts failed with Failed to fetch and remain recorded. Its reader remained locked, 307 replay rejected a disturbed stream, and disturbed/producer-error operations had no terminal outcome within 1.5 seconds. These are bounded observations, not claims that they never settle. MonkeySharp deliberately releases readers, rejects bad inputs promptly and replays staged bytes. Permission denial does not acquire a reader; a producer may independently prefill its own stream before this API receives it.

Step 30 keeps two features separate: running GM command callbacks and launching @run-at context-menu source. The latter uses captured document targets and one-shot context-private proofs on 84, so navigation cannot retarget an old menu to a new document. 121 emits its native message event asynchronously after disposing the borrowed IFrame; 151 lacks PostMessage in the tested isolated child context. Main-frame support is retained on both. No page ID, URL comparison or DOM marker substitutes for native identity. This is a scoped implementation; full step 30 acceptance is incomplete.

The beta native-menu fixture requires a pin with settings.headless=false and real native input, then its Save menu evidence button. The attempted automated run was stopped because the computer-use native pipe could not connect after retry/reset. No native selection was performed. Callback payload/WPF bridge checks and unit filters are not a beta native-click result.

The BFCache fixture uses cacheable HTTP A/B pages without unload/beforeunload, native back navigation and closure nonces plus pageshow.persisted. It runs once without a runtime/CDP observer and once with prepared raw and isolated GM. Default and explicit enable-features=BackForwardCache settings still produce new closures and persisted:false on the tested versions. This does not prove BFCache impossible in all CEF configurations; it denies a restoration guarantee for this route. Private contexts and suspended-state listener/storage recovery remain unverified because the basic cache-hit prerequisite was not met. Reproduce with `./scripts/compatibility/Run-NativeProbe.ps1 -Probe bfcache -CefSharpVersion 121.3.70 -Platform x64` and optionally `-EnableBackForwardCache`. Assessment success is separate from capability support.

OOPIF commands and events carry their native session. Context IDs are scoped within that session; remote objects pin each world generation. Only iframe targets whose native parent frame belongs to this executor receive bindings/source. Discovery can briefly attach a target to read native ancestry, then detaches its own session if unrelated; it never runs source there. Native CEF IDs are never cast to CDP IDs. Reserved CEF command IDs, owned-session detach and per-observer envelope filtering preserve other observers and shared domains. Read-only coexistence is tested; competing owners that mutate Target discovery/attachment state are not an independently isolated DevTools client.

The native fixture uses distinct sites, real iframe targets and actual prepared GM code. It checks two script partitions, nested targets, normal/private cookie jars, a permission denial with zero requests, same-process/OOPIF migration without duplicate source, and balanced document release. Targeted native menus, strict document-start, historical isolated webRequest and transparent BFCache remain separate limits. A same-site-subdomain first attempt was a negative control and is excluded as OOPIF evidence; overlapping version runs were invalidated and rerun serially. The gate now runs from Run-Baseline.ps1.

Step 33 now has separate [start and CSP decisions](start-csp-decision.md), with main/OOPIF and normal/private evidence, a bounded owned parser-pause candidate, actual GM effects and a separately scoped renderer deployment task. Strict start and CSP bypass remain unimplemented.

Step 36 preparation extends the NuGet-only consumer with actual incremental text, staged stream upload, menu event fields and isolated GM in a real iframe target. The 121/x64 package-only pilot passed all declared checks; it is not the final delivery. The earlier polling guard race and correction are retained in [pilot evidence](../../scripts/compatibility/evidence/enhanced-consumer-pilot-p1.json). Delivery now copies native OOPIF reports before cleaning successful worktrees.

During native process migration a borrowed CEF frame can retire between lookup and the location probe. Initialization skips that retired document when evaluation throws ObjectDisposedException and the frame is disposed or invalid; unexpected failures on live frames still report MSC101. Regression coverage checks both outcomes. The OOPIF gate now rejects MSC101/MSC231/MSC233/MSC236 initialization and dispatch diagnostics instead of accepting successful effects alone.

The strengthened 84/x86 gate also caught retirement after location resolution, during source dispatch. Dispatch checks IsDisposed before IsValid, since old CEF wrappers throw when reading IsValid after disposal. Confirmed retirement before/during dispatch cancels that operation without executing source in a replacement context; live-frame disposal exceptions still propagate. Native failure records include complete exception stacks.
